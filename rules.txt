Database table descriptions:

    recipe table: 
     - start_date indicates the date a batch starts (use a date type)
     - pouch_date indicates when the batch was completed and pouched (use a date type)
     - batchID is the unifying reference key across tables for the batch
     - batch is an increment on batch made
     - style is a categorical limited to the few types you have seen (pure,rustic,rustic_experimental)
     - kake must be a ingrdientID with a rice type or the designated kake_rice or koji_rice from the ingredient table
     - koji must be a ingrdientID with a rice type or the designated kake_rice or koji_rice from the ingredient table
     - yeast must be ingredientID with a yeast type from the ingredient table
     - starter must refer to a StarterBatch from the starters table (if one doesn't exist create one using standard 'Shubo' recipe from ingredient table, and associate the StarterBatch id following the starter batch naming scheme of 's##')
     - water_type is a categorical ingredientID from the ingredient table of the category water (spring, well, distilled)
     - total_kake_g running total of kake rice added to the batch across all the additions including the amount the batch was started with
     - total_koji_g running total of koji rice added to the batch across all the additions including the amount the batch was started with
     - total_water_mL running total of water in ml added to the batch across all the additions including the amount the batch was started with
     - ferment_temp_C is the temperature in C that the ferment was conducted at
     - Addition1_Notes any notes to add when first addition of kake rice and koji rice to the StarterBatch
     - Addition2_Notes any notes to add during the second addition of kake rice and koji rice to the batch
     - Addition3_Notes any notes to add during the thrid addition of kake rice and koji rice to the batch
     - ferment_finish_gravity is the measured specific gravity at our self determined end of ferment to be used on the formulas to do live all the calculations made (corrected gravity, ABV%, SMV)
     - ferment_finish_brix is the measured percent brix at our self determined end of ferment to be used on the formulas to do live all the calculations made (corrected gravity, ABV%, SMV)
     - final_measured_temp_C is the measured temperature in C at which final measurments took place
     - final_measured_gravity is a measured float value for the specific gravity of the final product
     - final_measured_Brix_% is a measured float value for perecent brix
     - final_gravity is a calculated formula using values from the table  if(not(isblank(final_measured_temp_C)), LET(  mt, INDEX(final_measured_temp_C, ROW()),  mg, INDEX(final_measured_gravity, ROW()),  ct, 20,  pmt, 0.999005559846799 - 0.000020305299748608*mt + 0.0000058871378337408*mt^2 - 0.00000001357811768736*mt^3,  pct, 0.999005559846799 - 0.000020305299748608*ct + 0.0000058871378337408*ct^2 - 0.00000001357811768736*ct^3,  ROUND(mg * pmt / pct, 4)),"") --- ct is calibrated temp for the hydrometer include an option to enter a different temp but default to 20
     - ABV_% is a calculated formula using values from the table  if(not(isblank(final_measured_temp_C)), let(b, index(final_measured_Brix_%, ROW()), fg, index(final_gravity, ROW()), round(1.646*b-2.703*(145-145/fg)-1.794,1)),"")
     - SMV is a calculated formula using values from the table  if(not(isblank(final_measured_temp_C)), let(fg, index(final_gravity, ROW()), ROUND(1443/fg-1443,1)), "")
     - final_water_addition_mL how much water was added to the final ferment to before proofing down for the final measurements?
     - clarified boolean if process was undertaken (can be check box)
     - pasteurized boolean if process was undertaken (can be check box)
     - pasteruization_notes if pasteurized process taken, what notes if any are there?
     - finishing_additions what final addtion notes are there?


    Ingredients table:
     - ingredientID indicates in-database reference for that ingredient
     - ingredient_type indicates what type of ingredient (category rice can be used for making koji or kake)
     - acc_date indicate accession date into the database as a defined ingredient
     - source is where the ingredient was acquired
     - description is extended description for the ingredient


    Starters table: Default entry fill to 'Shubo' from ingredient table which is "100ml of top crop liquid from previous batch Moromi; 250g Koji; 250ml H20; Run for 3 days at 6C before using in Moromi"
     - Date is the date the starter was created (should be a DATE type)
     - StarterBatch is a in-database ID (using notation s##) to be used when noting starting conditons of a batch
     - BatchID is the unifying ID for a batch across tables and the batch that this starter entry is going into
     - Amt_Kake is how much kake rice was added into the starter in grams and should contribute to the total_kake_g column in the recipe table
     - Amt_Koji is how much koji rice was added into the starter in grams and should contribute to the total_koji_g column in the recipe table
     - Amt_water is how much liquid was added to the starter in ml; water_type is a categorical ingredientID from the ingredient table of the category water (spring, well, distilled)
     - Kake is ingredientID for a rice or kake_rice type from the ingredient table
     - Koji is ingredientID for a rice or koji_rice type from the ingredient table
     - yeast is ingredientID for a yeast type from the ingredient table
     - lactic_acid should be grams of lactic acid solution added
     - MgSO4 should be grams of MgSO4 added
     - KCl should be grams of KCL added
     - temp_C is a temperature in C at which the starter began it's ferment


    PublishNotes Table: pared down version of details from the recipe table, using good puncutation and grammar for public view
     - BatchID the unifying reference key across tables for the batch
     - Pouch_Date indicates when the batch was completed and pouched (use a date type)
     - Style a categorical limited to the few types you have seen (pure,rustic,rustic_experimental)
     - Water is a categorical ingredientID from the ingredient table of the category water (spring, well, distilled)
     - ABV ABV_% value from recipe table for the corresponding batchID
     - SMV SMV value from recipe table for the corresponding batchID
     - Batch_Size_L total_water_mL from recipe table plus any final water or finishing additions volume converted to L
     - Rice description of kake_rice used in the batch coming from the ingredient table
     - Description tasting notes and brief sake recipe description.

Functionality:

    formulas page should be a couple of independent live calculators based on entered values, for mocking up and determining any final additions to add. use 'gui_app.py' Formulas tab as a basis which includes:
    entry fields for calibrated hydrometer temp (assume 20C or 15.6C), measured specific gravity, measured %Brix
    live calculate SMV and ABV% from corrected gravity and measured %brix values
    live calculate dilution or adjustments (using 35% Brix amazake ingredientID) to bring the final corrected gravity, %Brix, SMV, and ABV% to a target profile. Target profiles include: Pure (11% brix, 1.005 SG) and Mixer (12% brix, 0.995 SG). include dropdown adjuster ingredient_type to select what adjustment ingredient to use, reading the %brix from the description of that ingredient from the ingredient table

    Database View page:
    a scrollable data table preview of the database entries for review

    Google sheet sync page: option to initate sync with assoicated google sheet backup, default to the SakeMonkeyRecipeDatabase google sheet with sheets id: 1wGSiuApdScc-RULpSyecmA_km4J6k9KYOp0rz3nT2mM using the service_account.json credentials.

    add-ingredient: 
    - alphanumeric field for ingredientID for the new ingredient
    - drop down choice for ingredient_type, with option to create a new ingredient_type, list all available types by default
    - acc_date defaults to current date, but should be the date that the ingredient was included in batches, use a calendar pop-out for picking date if the date is not 'today'
    - alphanumeric field to detail the vendor source of the ingredient
    - alphanumeric field that can hold at least 300 character description of the ingredient and any other details to help describe the ingredient

    add-recipe:
    - alphanumeric field following the rules for a batchID definition ('??[R|P|M]') to indicate the batch and the trakerID across database tables
    - numeric field that should autoparse the batchID feild for the numeric component, to track the batch number, it should increment in the database, and provide a warning message if the new entry is a sinificant increment increase. If the batch number and batchID already exist, provide a warning, and suggest changing input to the 'update-recipe' tab.
    - style drop down, for which style the batch is following, (pure, rustic, rustic_experimental, mixer), with given option to create a new style in place.
    - calendar pop-out to indicate the start date of the batch, which should be 3 days after the starter_batch was started.
    - kake selection drop down, pulling ingredients from the ingredient table that have a 'ingredient_type' of kake_rice or rice, default select the last value of kake_rice in the ingredients table, and have all the rice and kake_rice ingredient_type ingredients available in the drop selction field
    - koji selection drop down, pulling ingredients from the ingredient table that have a 'ingredient_type' of koji_rice or rice, default select the 'koji50' ingredientID in the ingredients table, and have all the rice and koji_rice ingredient_type ingredients available in the drop selction field
    - yeast selection drop down, defaulting to the 'Prop_sake9' yeast ingredient from the ingredients table, and have all yeast ingredient_type options available in the drop down
    - water selection drop down, with all water ingredient_type ingredients available in the drop down
    - for starter selection have a starterbatch dropdown. the starterbatch dropdown should default to the 'Shubo' starter batch which is 250g Koji, 250ml Water, .4g Lactic Acid at 6C, with a start date of 3 days before the recepie start date, display a warning notification if it is not, and ask for user amendment if it's wrong
    - when creating a new recipe, the ferment_temp_C field should default to 6C

    update-recipe:
     - drop down menu on which batchID to update
     - drop down menu to select what kind of update to perform on the batch: addition1, addition2, addition3, ferment_finish measurements, batch finishing
        - Addition1,Addition2,Addition3:
            - kake_rice addition: numeric field indicating in grams how much kake rice was added on the addition to the Moromi
            - koji_rice addition: numeric field indicating in grams how much koji rice was added on the addition to the Moromi
            - Addition[1|2|3]_Notes: text field to detail any addition notes or comments at the addition
        - ferment_finish measurements:
            - ferment_finish_gravity
            - ferment_finish_brix
        - batch finishing:
            - final product measuring temperature: float number entry
            - calibrated measuring temperature: drop down to select 15.6C or 20C
            - final product measured Brix%: float number entry
            - final product measured gravity: float number entry
            - final_water_addition_mL
            - clarified boolean checkbox
            - pasteurized boolean checkbox
            - pasteurization_notes: text field to detail any addition notes or comments at the batch finish when pasteurizing
            - finishing_additions: text field to detail any addition notes or comments at the batch finish for adjusting to target profile
            - publish comment: text field to detail the final front face description/comment for the batch to be pulled into the publishNotes data table.
            - pouch_date: calendar date selector for describing the date which the batch was pouched
